# 使い方

## 画面の使い方

1. タスクを追加し、カテゴリ・期限・メモを整理する
2. 詳細の「リンクをコピー」を押す
3. xangiの会話に貼り付けて取得・更新を頼む
4. 作業中・完了を必要に応じて切り替える

手入力のタスクは右下の「＋」ボタンから追加フォームを開いて作れます。閉じるボタンやEscで閉じても入力は保持され、追加に成功するとフォームを閉じて「Open」一覧へ戻ります。Ctrl/⌘+Enterは開いているフォームを送信します。タッチ端末では入力欄をタップしてからキーボードを開きます。画面はxangiと同じナビゲーション、テーマ、配色、余白、リスト表現に揃えています。

## 起動

[xangi拡張への登録](../XANGI_SETUP.md)に従い、xangiの「拡張」から利用します。設定はアプリルートの`.env`に保存し、起動元の同名環境変数があればそちらが優先されます。

- `XANGI_URL`: 依頼先xangiのWeb API。省略時はxangiが渡す接続先を使用
- `XANGI_TOKEN`: xangi APIのBearer token。未指定なら`XANGI_EVEN_TERMINAL_TOKEN`
- `XANGI_PROVIDER`: `codex`または`claude`。既定`codex`
- `XANGI_TASKS_DATA`: タスク保存先。既定`.data/tasks.json`、アプリルート基準
- `XANGI_TASKS_POLL_MS`: 実行中タスクの同期間隔。既定`3000`

## 開発

```bash
npm run lint
npm test
npm run build
```

## Inbox API

```bash
xangi tool extension_request --id xangi-tasks --capability xangi-tasks.manage \
  --path /api/inbox --method POST \
  --body-json '{"title":"仕様案の返信を待つ","type":"waiting","sourceText":"明日までに仕様案を送ります","dueRaw":"明日まで"}'
```

`type`は`action`、`waiting`、`hold`のいずれかです。候補作成は内部操作ですが、正式タスク化、外部サービス更新、対外送信は人の確認後に行います。

## 接続と保存先

`XANGI_TOKEN`には接続先xangiのterminal API用トークンを設定します。未指定時は`XANGI_EVEN_TERMINAL_TOKEN`も利用できます。ブラウザへトークンは送信しません。

xangiへログインして「拡張」から開きます。拡張への接続用キーはxangiが管理します。

`XANGI_TASKS_DATA`で保存先を指定します。相対パスはアプリルートを基準に解決し、省略時は`.data/tasks.json`を使用します。

## 動作確認

1. テスト用タスクを追加し、リンクをコピーします。
2. リンクを開き、同じタスクの詳細が表示されることを確認します。
3. 拡張APIからタスクを取得し、メモを更新します。
4. 再読み込みで反映を確認してから「完了」を選びます。

## トラブルシューティング

- 接続失敗: xangiのWeb Chat起動、URL、terminal APIトークンを確認します。
- タスクが見えない: 画面のフィルターと`XANGI_TASKS_DATA`を確認します。
- `failed`: エラー内容を確認して接続を修復し、再依頼します。

[READMEへ戻る](../README.md) · [設計](design.md)

画面上部の別チャットへのリンクはありません。タスクのリンクをコピーしてxangiへ渡せます。

候補はカテゴリメニューの「Inbox」で開き、「採用してOpenへ」で選別できます。手入力のタスクもOpenに入ります。Openには未完了のタスクを、Closedには完了と却下を表示します。実行状態は別の項目で確認できます。一覧の「削除」は確認後にxangi-tasksから非表示にし、xangiの会話履歴には影響しません。実行中・依頼中は削除できません。データにはdeletedAtを保存し、一覧・取得・更新の対象から除外します。削除APIは`DELETE /api/tasks/:id`です。

xangiの拡張から開くには[XANGI_SETUP.md](../XANGI_SETUP.md)を参照してください。xangiが本体を起動・管理します。

各タスクの「編集」でタイトル・背景・期限を変更できます。期限は日付指定で、通知や自動実行は行いません。タスクのリンクをコピーしてxangiへ渡せます。

## 期限順・繰り返し

一覧の「並べ替え」で追加順・期限が近い順・遠い順を選びます。期限なしは末尾。状態タブと併用でき、並び順はブラウザに保存されます。状態タブの件数は選択中のカテゴリに一致するタスクを数えます。Inboxの候補はカテゴリ一覧と件数から除外されます。Openタスクの期限が日本時間の昨日以前の場合、一覧に「期限切れ」と表示します。

作成・編集の「繰り返し」は毎日・平日（月〜金）・毎週・毎月・毎年・カスタムから選べます。カスタムは1〜999日/週/月/年ごと。週は複数曜日を指定でき、未選択なら初回期限の曜日です。期限未指定で繰り返しを設定すると、日本時間の今日が初回期限になります。

「完了」で履歴を残し、次回分を未着手へ1件追加します。未着手も手動で完了できます。次回分はタイトル・説明・繰り返しを引き継ぎ、会話・実行結果は引き継ぎません。次回分を自動実行・通知する機能ではありません。停止するには次回分を編集して「繰り返さない」を選ぶか削除します。完了済みの回を編集しても次回分には反映されません。

日付は日本時間の日単位です。遅れて完了した場合、期限と完了日の両方より後の予定日まで進み、過去分をまとめて作りません。週の区切りは月曜日。月末は存在する最終日に補正し、翌月以降は元の日付に戻します（1/31→2/28→3/31）。うるう年も同様です。期限・繰り返しを編集するとその回の期限が新しい基準になります。

選択肢は[Microsoft To Do公式ヘルプ](https://support.microsoft.com/en-us/todo/add-due-dates-and-reminders-in-microsoft-to-do)を参考にしています。遅延完了・月末などの詳細は上記のxangi-tasks仕様で、Microsoft製品との完全互換やデータ同期は保証しません。

### 開始画面とタスク参照

選択したカテゴリ、フォルダの開閉、表示タブ、並び順は同じブラウザで次回も復元します。削除済みのカテゴリは「すべてのカテゴリ」に戻ります。端末間の同期は行いません。

初回はOpen、次回以降は最後の表示タブで開きます。「リンクをコピー」は現在のxangi-tasks画面のURLに`?task=<ID>`を付け、開くと対象の詳細を表示します。コピー権限がない場合は手動コピー用の入力欄を表示します。

Openの進捗は状態横に「未着手」「作業中」「確認待ち」などで小さく自動表示します。画面に進捗の選択欄や着手・リセットボタンは置きません。連携から進捗を変更するAPIは `POST /api/tasks/:id/execution/start` と `/execution/reset` です。タスクの状態はOpenのままです。Closedから戻す場合は `/open` を使います。

## 内容を直接編集する

タスクを開くと、タイトルと「背景・完了条件」をその場で書き換えられます。「編集」を押す必要はありません。入力欄を離れると保存し、タイトルはEnter、本文はCtrl/⌘+Enterでも保存できます。本文のEnterは改行です。日本語変換中のEnterでは保存しません。期限とカテゴリも直接変更できます。繰り返しは「繰り返し・詳細設定」から変更します。

保存状況を画面内に表示します。保存に失敗した入力は保持され、「保存を再試行」で再送できます。未保存・保存中は詳細を閉じず、保存完了後に閉じます。4秒ごとの再取得でも編集中の入力は置き換えません。

## 自分用のメモ

タスク詳細の「メモ」は背景・完了条件とは別の自由記入欄です。最大10000文字で、途中経過や思いつきを改行付きで保存できます。入力欄を離れるかCtrl/⌘+Enterで保存し、失敗時も入力を保持して再試行できます。メモはxangiへの依頼文には自動で含めません。繰り返しタスクの次回分へは引き継がず、その回のタスクに残します。

## カテゴリ・フォルダと右側の詳細

スマホ（幅900px以下）ではカテゴリ一覧を通常は隠します。左上の「☰」で開き、カテゴリを選ぶとタスク一覧へ戻ります。「×」、メニュー外のタップ、Escでも閉じられます。タスクの「⠿」をドラッグし始めると移動先のカテゴリが開き、移動終了・キャンセルで閉じます。カテゴリ同士の整理はメニューを開いて行います。

左側の「＋ カテゴリ」「＋ フォルダ」から分類を作成できます。フォルダはカテゴリをまとめる1階層のグループです。カテゴリ横の「…」から名前や所属フォルダを変更できます。タスクは1つのカテゴリに所属します。分類を作る前のタスクは「未分類」に表示されます。カテゴリと状態の条件は組み合わせて絞り込めます。

タスクを選ぶとPCでは右側に詳細を表示し、一覧の別のタスクを直接選べます。「×」またはEscで閉じられます。900px以下では一覧の上に詳細を全面表示し、閉じると一覧に戻ります。編集中の変更は保存してからタスクを切り替えます。保存に失敗した場合は入力を残します。

詳細と追加フォームでカテゴリを選べます。繰り返しの次回タスクも同じカテゴリを引き継ぎます。中身のあるカテゴリ・フォルダは削除できません。先にタスクやカテゴリを移してください。

バックアップする場合は`XANGI_TASKS_DATA`で指定したタスクJSONと、そのパスに`.collections.json`を付けた分類JSONを一緒に保存してください。設定JSON（`.settings.json`）も保存してください。

### Notionに保存

画面上部の「設定」で、接続許可済みのNotion親ページURLを一度保存します。タスク詳細の一番下にある「タスクのページを作成」を押すと、その親ページの下にタスク専用ページを作ります。作成後は「タスクのNotionページを開く」から移動できます。「既存ページを使う」から直接関連付けることもできます。親ページ設定は端末間で共通です。設定を変更・解除しても、作成済みのタスクページは移動・削除しません。

「ファイルを保存」は選んだファイルをタスクのNotionページに添付します（空でない20 MiB以下、Notion側の形式・プラン制限も適用）。

認証は既存の `xs-notion-manager` と同じ `~/.config/notion/api_key` を読みます。xangi-tasksを同じOSユーザーで起動してください。別の場所なら `XANGI_TASKS_NOTION_KEY_FILE` で指定します。キーをブラウザやタスクJSONへ保存しません。

ページ作成時に通信が切れた場合は重複防止のため自動再作成しません。Notionで作成結果を確認し、作成済みページをリンクしてください。添付のタイムアウト時もNotion側を確認してから再操作してください。

リンクコピーはClipboard APIと選択コピーの順に試し、両方失敗した場合だけ手動コピー欄を表示します。

タスク名または左の「⠿」をカテゴリにドラッグすると所属を変更できます。「未分類」へドロップするとカテゴリから外せます。カテゴリ名または「⠿」をフォルダ名へドラッグすると、そのフォルダへ移動します。ドラッグ中に現れる「フォルダの外へ移動」へ置くとフォルダから外せます。タスクを閉じたフォルダ名へ重ねると中のカテゴリが表示されます。

タッチ画面では「⠿」を動かします。通常の行はこれまでどおりスクロールできます。移動できる場所は枠と背景色で表示します。つまみをクリック、またはキーボードで選んで実行すると、カテゴリ・フォルダの選択フォームを開けます。保存に失敗したときは通知し、サーバーの保存内容を再読み込みします。

## xangiから取得・更新する

拡張`xangi-tasks`の`xangi-tasks.manage`を通じ、`GET /api/tasks/<ID>?history=0`で取得、`PUT /api/tasks/<ID>`でタイトル・説明・メモ等を更新できます。状態は`POST /api/tasks/<ID>/execution/start`、`/execution/reset`、`/open`、`/close`で変更します。認証は既存の拡張経路を使い、コピーするリンクにキーは含みません。

画面の「xangiへ依頼」から直接依頼できます。会話リンクからxangiを開けます。候補は「候補」タブ、依頼中・実行中は「作業中」から確認できます。

## エージェント・Projectを選んで依頼する

処理中以外のタスク詳細で「xangiへ依頼」を押します。Projectなしなら登録済みエージェントを選びます。Projectを選ぶと、その担当設定を使います。Discord・Slackチャンネルが設定されたProjectでは、そのチャンネルにスレッドを作成して依頼・返信を同期します。送信先はフォームに表示されます。

「この依頼先を既定にする」は設定だけを保存し、実行しません。次のタスクから他の端末でも同じ設定を使います。再依頼はタスクの前回設定を優先します。

送信内容はタイトル・背景と完了条件・期限・追加指示です。メモは自動では送りません。依頼後は「作業中」へ移り、「xangiの会話を開く」で結果を確認します。xangi-tasks独自の実行結果欄はありません。

開いている会話には追加で依頼します。新規にしたい場合はxangi側でその会話をクローズしてから依頼してください。依頼先の変更も先にクローズが必要です。タスクの完了は会話をクローズしません。

`GET /api/projects`でProjectを取得します。`GET /api/settings`と`PUT /api/settings`は`agentId`・`projectId`を取得・保存します。`POST /api/tasks/<ID>/delegate`でも指定でき、省略は保存済みの既定設定、`projectId`の空文字はProjectなしです。Project指定時はエージェント欄を使いません。設定はタスクJSONの`.settings.json`サイドカーへ保存します。

タスクリンクの`?task=<ID>`は、完了済みも含めて直接取得し、すべての一覧から詳細を開きます。見つからない場合はエラーを表示します。

xangiからの操作は同梱の[タスク用スキル](../skills/xs-xangi-tasks/SKILL.md)を利用できます。

## Export / Import

設定の「Export」は全フォルダ・カテゴリ・タスク（候補・完了済みを含む）・設定をJSONで端末に保存します。Notionは不要です。削除済みタスクと認証キーは含みません。

「Import」は20 MiB以下のExportファイルを選択し、内容を確認してから既存データを全置換します。置換前のデータはサーバーへ自動退避します。確認後にデータが変わった場合やタスク実行中は拒否します。ファイル内の実行中タスクは要確認になり、自動再実行しません。Notion設定もファイル内の値に戻りますが、Notionの実ページ・ファイルやxangiの会話は復元・削除しません。

## メール・会話・カレンダーからの候補収集

同梱のxs-xangi-tasksスキルから「メール・会話・カレンダーから候補を拾って」と依頼できます。xangi-mailの重要メールAPI・本人の会話ログ・指定したGoogleカレンダーをxangi-tasks側で読み、原文・後続の文脈・既存タスクを照合して候補を登録します。各取得元は単独でも利用できます。カレンダーは認証済みgogcliと `--calendar-config` の設定が必要です。候補はInboxで確認し、採用するとOpenへ移ります。手順と定期実行例は[候補収集](../skills/xs-xangi-tasks/references-candidates.md)を参照してください。

`POST /api/inbox` は任意の `sourceKey`（300文字以内）を受け付けます。同じキーは却下・削除済みも含め既存レコードを返し、重複追加しません。`GET /api/inbox/capabilities` の `sourceKeys:true` と `statusModel:2` で対応を確認できます。収集結果の保留・無視はスキル側の非公開状態ファイルに保存します。

Inboxはカテゴリメニューの先頭から開きます。候補には既存カテゴリを仮設定でき、一覧に「仮: カテゴリ名」と表示します。詳細で必要ならカテゴリを直し、「採用してOpenへ」で採用します。カテゴリを変更しただけでは採用しません。

ラベル機能は削除しました。ラベル付きの旧ExportはImport対象外です。既存環境の更新時は拡張を停止し、`node scripts/remove-task-labels.js <tasks.json> <新しいファイル.json>`でラベルを削除したデータを作成してから置き換えます。元ファイルは退避し、タスク本体・カテゴリ・期限などは保持します。
